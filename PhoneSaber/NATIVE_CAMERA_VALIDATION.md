# 低遅延取得の検証記録

確認日: 2026-09-06。Larixを使用しないAVFoundation直接取得経路の追加。

## 確認済み

- Macの実際のデバイス一覧を読み取り、iPhoneに640×480・1280×720などの30/60FPS形式があることを確認。
- iPhoneがdeviceTypeではExternalと報告される場合も、isContinuityCamera=trueで区別できることを確認。内蔵カメラへの自動フォールバックはしない。
- Objective-CアダプターをこのMacのclangでビルドし、Pythonからロード・デバイス一覧取得に成功。
- `python3 -B -m unittest discover -v`: 7件成功。
- ネイティブテストは5000回のフレーム更新を含み、最新フレームのみの保持、行間パディング除去、小さい出力領域への書き込み防止、同時読み書き、サイズ変更を確認。
- PythonテストはBGRA→BGR変換後のデータ所有権、時刻変換、重複フレーム排除、二重終了を確認。
- 測定マーカーの生成・読み戻し、未知ID・重複・不正時刻の除外、計測終点の統一を確認。
- 赤・青の検知、肌が接触した発光棒の軸、追跡失効後の再確認について既存テスト成功。
- `git diff --check`: 問題なし。
- `MallocScribble=1 MallocGuardEdges=1`でネイティブテスト成功。環境由来のIOSurface警告は出たため、これを実カメラの動作証拠には使わない。

## 未完了・制限

- このアプリからのカメラ許可はauthorization_status=0（未決定）。映像取得は未成功。初期エラーメッセージは未決定のタイムアウトを拒否と表示していたため修正した。
- 640×480/60FPSは対応形式の列挙結果であり、その設定で実際に連続取得できたという証拠ではない。
- 無線を含む遅延の削減幅、本番の棒検知精度は未測定。「最速」「改善済み」とは判定していない。
- Swift方式は既存開発環境のSwiftBridgingモジュール重複でビルドできなかったため撤回。Swiftソースは残していない。
- AddressSanitizer版はサニタイザーの初期化時に失敗（sanitizer_malloc_mac.inc:189）。ASan検証済みとは扱わない。通常のネイティブテストは別途成功。
- 連係カメラ内部の無線エンコードサイズ・ビットレートは公開APIから取得できていない。Macの取得サイズを通信サイズと同一視しない。

## 最終選定に必要な実測

1. カメラの利用を許可し、`camera_benchmark.py --optical`で同じiPhone・位置・照明のまま4設定を比較する。
2. 測定を3回以上繰り返し、実際の画像サイズ・FPS・通常時の遅延・遅い側の遅延を比較する。表示更新の粒度より小さい差は優劣と断定しない。
3. 速い候補で赤・青の遠距離・高速移動・交差・赤い服の背景を試す。精度を落として速くなっただけの設定を採用しない。
4. 選んだ設定で長時間の取得、切断・再起動、IMU・Unityへの座標送信も確認してから既定値を変更する。

実行方法と計測値の意味はSMARTPHONE_CAMERA.mdを参照。
