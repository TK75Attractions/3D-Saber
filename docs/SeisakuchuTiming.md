# Zero -狂奏曲-：BPM98と変拍子の小節マップ

2026-10-13、ユーザーの「BPMは98」という訂正と、再添付された「メトロノーム入りです。.mp3」を基準に更新。曲IDは引き続き `製作中`。以前のBPM196という表記を訂正した。

Easy・Normal・Hard・互換用 `chart.json` をBPM98へ統一した。ノーツの `time`、座標、種類、色、方向、切断回数、ロング長さ、個数、並び順、および `offsetMs` は変更していない。音源・演出区間・表示難易度も維持する。変更するノーツの値は、編集用の四分音符単位の `beat` だけ。

添付のSHA-256は以前の解析対象と一致したため、通常クリック770Hzと強拍の2090/4550/5930Hzを独立に照合した既存解析を再利用した。クリック間隔約0.306122秒はBPM98の8分音符。四分音符としての測定BPMは約98.000035で、格子に対する時刻照合誤差の95パーセンタイルは約1.25ms。これは解析上の誤差であり、実機入力遅延の測定値ではない。

音源上の拍原点は20ms。Easy・Normal・互換用は `beatZeroMs:20`、`offsetMs:0` を維持し、旧beatを半分にした。作者作成のHardは元のBPM120から変更し、`offsetMs:110` を維持するため `beatZeroMs:-90` とした。これで全難易度の小節線とクリックが `beatZeroMs + offsetMs = 20ms` にそろう。Hardのbeatは `(time + 90) × 98 / 60000` で求め、ノーツ時刻を格子に丸め直していない。

エディターで別の設定を変更した際に負の原点が0へ戻される問題と、先頭クリック・試聴開始位置がOFFSET加算前に0へ丸められる問題も修正した。既存の補正を残したまま、再保存後も小節線とメトロノームを同じ位置に保つ。

クリックは558個（8分音符番号0〜557）、強拍は99箇所。14区間の拍子設定で小節頭を合わせる。クリックのまとまりをそのまま5/8・4/8・11/8・6/8と表記し、小節頭の絶対時刻は以前の解析から変更しない。最後の6/8は、8分音符番号552の強拍と後続5クリックから推定した終小節であり、次の強拍による確定ではない。

添付とゲーム音源のSHA-256、全99小節の照合時刻は [解析データ](../Tools/ChartDesign/Seisakuchu/metronome-timing.json) に記録。現在のゲーム音源との40〜550Hz帯域の波形照合は2〜168秒の11区間で行い、遅れは−0.375〜+0.125ms、相関は0.535〜0.864だった。音色・ミックスには差があるが、今回の比較区間で拍原点を移す根拠となる時間差は検出されなかった。添付は174.864秒、ゲーム音源は余韻を含め178.224秒で、音源は差し替えていない。

旧初稿の生成器や以前のBPM196への変換スクリプトで、現行譜面を再生成しない。ユーザー作成のHardを含むノーツはそのまま保ち、拍子情報の保守は現在のBPM98・拍原点・小節マップに基づいて行う。

検証済み: 4譜面の小節頭99箇所・558クリックが一致し、添付クリックとの最大誤差は約1.27ms。ノーツのbeat以外の全値、既存のタイミング補正、音源・stage・metaは変更前と一致した。Unity 6000.3.9f1の関連EditModeテスト62件成功。負の原点を持つ譜面のエディター再保存、小節線、8分音符メトロノーム、先頭からの試聴を含む。実機プレイでの聴感確認は未実施。
