# 製作中：メトロノームに基づく拍・小節の更新

2026-10-06、提供された「メトロノーム入りです。.mp3」を基準に更新。BPM196の四分音符として数える指定をユーザーから受けた。

BPMは98→196、`beatZeroMs:20` と `offsetMs:0` は維持。全難易度と互換用 `chart.json` の `beat` を2倍にした。各ノーツの `time`、座標、種類、色、方向、切断回数、ロング長さは変更していない。ゲームでは引き続き元のクリックなし音源を再生する。

提供クリックは約0.306122秒間隔。周波数の異なる通常クリックと強拍を、複数帯域の波形照合で区別した。測定BPMは約196.000071、格子に対する時刻照合誤差の95パーセンタイルは約1.25ms。これは解析の照合誤差で、実機入力遅延の測定値ではない。

クリックは558拍（拍番号0〜557）、強拍は99箇所。14区間の拍子設定で小節頭を合わせる。最後の6/4は、552拍目の強拍に続く5個の通常クリックと、その後クリックが止まることから置いた終小節。次の強拍による確定ではない。音源末尾は余韻を含む174.864秒。

音源のSHA-256と全99小節の照合時刻は [解析データ](../Tools/ChartDesign/Seisakuchu/metronome-timing.json) に記録。従来の全編4/4という仮設定と、音楽の反復から作った試聴用の小節推定より、今回の提供クリックを優先する。

旧初稿用スクリプト `Tools/Seisakuchu20261006/build.py` は作業フォルダ側にあるBPM98基準の生成器で、この改訂の再生成元ではない。実行すると今回の拍子マップを上書きするため、再生成時は本解析データのBPM・拍原点・拍子変更を引き継ぐ。

検証: 全4譜面の小節頭99箇所を提供クリックと照合し、全ノーツのbeat以外の値と原音源のSHA-256が変更前と一致することを確認。Unity 6000.3.9f1の関連EditModeテスト58件成功（ChartMeterMap、ChartLoader、ChartContent、SongChartAvailability、SongPreviewWindow、SongStagePerformance）。実機プレイでの聴感確認は未実施。
