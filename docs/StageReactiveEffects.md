# プレイ操作に応えるステージ演出

2026-09-18。音ゲー8作品を比較した提案から、斬撃の伝播、サビの収束と展開、同時斬り・ロング完走の反応を実装。

## 見え方

- 通常の切断：担当する側の床に光の波が走り、側面の照明が手前から奥へ連鎖する。
- 譜面上の同時斬り：別の手で同時刻のノーツを短時間内に切ると、片側の波が一つの左右対称の波と外側の弧へ変わる。
- ロング：各打で側面の7段の光が充填され、完走で二重の弧が外向きにほどける。途中終了では完走の解放を出さない。
- サビ：登録済みの強い演出区間の前に光が奥へ集まり、直前に追加照明が弱まる。区間の頭でビームが外へ開き、床に波が走る。サビの演出は成功・失敗や難易度に依存しない。

すべて既存11背景へ共通の表示層として重ねる。背景の色調に合わせた配色を持ち、プロジェクター設定では追加光の強さを下げる。カメラ、ノーツ移動、判定、譜面、音源は変更しない。

## 接続と境界

`StageReactiveEffects` は `GamePlayManager` が曲読込後に生成し、`NoteSpawner.OnNoteSpawned` からノーツを購読する。新しい `OnChartReset` で購読と一時表示を片付ける。独立したUpdateは追加せず、曲再生中の既存ループから曲時刻を渡す。

`StagePerformanceTimeline.EvaluatePresentation` は従来の滑らかな区間強度を保ち、予兆・直前の抑制・入口の強調を別に評価する。区間の `anticipationSeconds`（既定2.4秒）と `impactSeconds`（既定0.8秒）を0にすれば、それぞれ省略できる。強度0.65未満の助走区間には入口の強調を適用しない。区間時刻は音源先頭基準で、個人の判定補正を含めない。

**アンダルシアは既存の区間指定が空のため、サビの時刻演出は出ない。** 斬撃・同時斬り・ロング反応は利用できる。音量や譜面密度からサビを推測して付ける処理は追加していない。将来、試聴して見せ場を指定できる。

波は最大10個で、同時に多く出ると明るさを抑える。表示用のメッシュと材質は各1個。光の形は床と中央通路の外側へ配置する。途中達成ロングがスコア用にOnCutを通知する場合も、IsCutとIsMissedを確認して成功演出と区別する。曲停止では波も止まり、巻き戻しでは古い波を消す。

## 次に検討したい演出

今回の3つとは別の追加案。以下は未実装。

1. **フレーズが完成する反応**：短い音楽フレーズをうまく斬り終えると、奥の紋章が一段完成する。毎打の短い光より長い、数秒単位の達成感になる。難易度別の必要打数や休符を考慮し、全ノーツ数の単純な閾値にしない。
2. **ラスサビだけの空間変化**：前半のサビは側面が開く程度にし、最終ピークでは遠景の大きな構造が現れる。海底遺跡の光輪、宇宙の軌道リングなど、背景ごとに一つの主役を決める。
3. **最後の一振りから余韻へ**：最後のノーツの成功反応と音源の終わりを分け、最後の一打で光を広げ、音が消えるにつれて奥へ収束する。Full Combo達成時だけ追加の光輪を重ねる。
4. **休符で見える舞台**：ノーツの少ない区間では遠景の動きを少し広げ、密集する直前に中央付近の明るさを落ち着かせる。操作中と観賞できる時間の差を作る。
5. **コンボの節目の短い祝福**：現在の数字の拡大と連動して周辺を一度光が巡る。同じ節目へ復帰するたびに繰り返さない。

次は「ラスサビだけの空間変化」を推奨。今回の一振り単位の手応えと入口の変化に加え、曲全体を通じた発展ができる。いずれも中央へ大きな文字や絵を重ねず、ノーツの視認性を優先する。
