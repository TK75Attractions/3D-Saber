# Zero -狂奏曲-：作者版Hardからの改作

2026-10-13、第3稿。曲ID `製作中` のHardで、拍から外れていた打点と連続フリックを修正した。第2稿に残っていた作者版の手置き時刻には、確認済みの98 BPMの拍より50〜100msほど遅い箇所が多かった。音源の立ち上がりとメトロノーム由来の拍原点を照合し、同色の2連・3連を往復するフリックへ変更した。

## 残した見せ場

3組の同時ロングは開始を拍に合わせた。横位置・色・方向、切断回数・制限時間・高さは第2稿を維持。約89秒の超ロングは左右50回・21.677秒、残数表示が追加単発と重ならない高さ（y=-0.3）のまま。下表の開始秒は音源上の時刻（`time + offsetMs`）。

このゲームのロングは、制限時間内に表示された回数だけ繰り返し切るノーツ。各切断の等間隔入力を要求しない。超ロング2本の共通期限は音源上110.473秒。途中の矢印なし単発8個は、左右の外側上段（x=±2.5、y=1.5）の固定レーンに残し、時刻を拍へ合わせた。検証・録画用の50回の経路は、単発へ手を伸ばして戻る時間を空けながら8分拍に載せる。最後の切断は期限内の110.224秒。実際のプレイヤーにこの経路を強制する変更はない。

## 改作の狙い

- 赤赤→青青の2連40組と、赤赤赤→青青青の3連24組を維持。18〜29秒・41〜46秒・54〜60秒・64〜76秒・111〜119秒・134〜148秒・159〜164秒付近で、連打の全ノーツを往復フリックにした。
- 3連には「←→←」9組、「→←→」7組、「↓↑↓」5組、「↑↓↑」3組を配置。中心から±0.28の位置も矢印と一緒に往復させ、同じ方向を連続で要求する空振りの構え直しを避ける。2連にも左右・上下と少量の斜め往復を使う。
- 連打の入口・出口と自由切りの実際の振り方向まで含めて、全曲を通して成立する経路を選ぶ。句末・同時アクセントの矢印は、この経路を壊さない範囲に絞った。
- 同時切り19組・同時ロング3組に加え、終盤の片手ロングと反対の手の応答2組も同じ拍にそろえた。静かな区間の休符、ノーツ数、ロングの回数・制限時間は維持する。

## リズム修正の根拠

確認済みの音源上の拍原点20ms、98 BPM、変拍子マップを使い、今回のHardの打点は8分拍にそろえた。全体OFFSETは変更していない。密な連打を個別に四捨五入すると2打が同じ拍に潰れる箇所があるため、元の順序と打数を保つ経路を選ぶ。別の手の入力が120ms以内に割れていた応答は同じ拍へまとめ、最後の同時打ちは参照音源の最終クリック（170.530秒）へ合わせた。

270ノーツ中234個を1ms超修正し、うち177個は40ms超。最大移動は最後の同時打ちの約205ms。例として6.235→6.142秒、66.610→66.449秒、88.860→88.796秒。音源の正規化された立ち上がり強度（±45ms内の正のスペクトルフラックス）の平均は0.703→0.935となった。これは音響的な補助指標であり、楽器を分離して全音符を採譜した証明ではない。メトロノーム解析の根拠は [BPMと小節マップ](SeisakuchuTiming.md) を参照。

録画のロング切断音も8分拍へそろえた。期限を等分した切断音で不用意なハネが生じないよう、回数を満たす拍を期限内から選ぶ。ゲームのロング判定仕様には変更を加えていない。

## 検証

Unity 6000.3.9f1の本編ローダーで、超ロング2本の共通制限時間・50回・単純な外側単発、その他の同時ロングの時刻以外の保持、OFFSET込みの実再生時刻と8分拍の一致、速い同色フリックの切り返しと進入方向を確認する。生成時はヘッダーの一致、全ロングの各切断、座標、音源長、矢印への進入と振り抜きを検査する。超ロング中の単発前後は、往復距離に応じて連打の切断時刻に余裕を置いた。

自動プレイの検証は `cut-plan.json` の経路を使い、切断時刻・位置・ロング内の連番と回数、超ロング中の追加単発の視認性を照合する。これはスクリプトで判定を投入する本編動作確認であり、センサー入力や実際の手振りのテストではない。実行後は撮影用スクリプトを削除し、ユーザーのシーン・ウィンドウ配置・設定・スコアを復元する。

第3稿の検証結果: 関連EditModeテスト52件成功、本編はResultまで到達し270ノーツすべてPerfect。録画の全424切断が計画と一致した（超ロング合計100切断）。追加単発8個の出現から切断まで241フレームを確認し、全て画面内、ロング本体との投影矩形の重なりは0。残数文字の余白・縁を含む外接矩形との重なりは最大約0.44%だった。`verify_capture.py` と `autoplay-validation.json` に照合処理・結果を残す。録画用の振り幅も経路監査と同じ前後0.25にした。確認したカメラ設定・720p録画での結果であり、全設定や実機入力を網羅した結果ではない。

動作経路の検査は、金ノーツを左右の位置に対応する手で切る経路に基づく。金ノーツのすべての手の選択や、実機での振り心地を保証するものではない。
