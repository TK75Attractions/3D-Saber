# Zero -狂奏曲-：作者版Hardからの改作

2026-10-13、第2稿。曲ID `製作中` のHardを作者版から改作し、その録画へのフィードバックを反映した。超ロングの制限時間を統一して左右50回にし、2連・3連、フリックの句読点、超ロング中の少量の単発を加えた。

## 残した見せ場

3組の同時ロングは開始時刻・横位置・色・方向を維持した。約89秒の超ロングだけ、左右の長さと切断回数を変更し、残数表示が追加単発と重ならないよう高さを約0.21下げた（y=-0.3）。他2組の同時ロングは全フィールドを維持した。下表の開始秒は音源上の時刻（`time + offsetMs`）。

| 開始秒 | 左の長さ・切断回数 | 右の長さ・切断回数 |
| --- | --- | --- |
| 34.360 | 4.926333秒・11回 | 4.918333秒・11回 |
| 88.860 | **21.677秒・50回** | **21.677秒・50回** |
| 148.235 | 3.750秒・9回 | 3.750秒・9回 |

このゲームのロングは、制限時間内に表示された回数だけ繰り返し切るノーツ。各切断の等間隔入力を要求しない。超ロング2本の共通終了時刻は音源上110.537秒。作者版の音取りから矢印なしの単発を8個戻し、左右の外側上段（x=±2.5、y=1.5）の固定レーンへ配置した。単発へ手を伸ばして戻る間は連打を休める、50回の切断経路を検証・録画用に用意した。実際のプレイヤーにこの経路を強制する変更はない。

## 改作の狙い

- 赤赤→青青の2連と、赤赤赤→青青青の3連を、18〜29秒・41〜46秒・54〜60秒・64〜76秒・111〜119秒・134〜148秒・159〜164秒付近へ混ぜた。同じ手の連打はコンパクトな上下配置にする。
- フリックは主に2連・3連の最後、同時切りのアクセント、譜面全体の休符へ入る句末に置いた。次の手だけが休む間隔を句末とは扱わない。全打点に向きを要求せず、準備・切断・振り抜きがつながる経路を検査した。
- 通常の同時切り19組と同時ロング3組、片手ロング中の応答、静かな区間で密度を下げる構成を維持した。
- 作者版の単発打点を優先した。45ms以内に分かれた左右ペアは中心時刻にそろえ、追加打点は指定した空き区間の音の立ち上がりを照合した。全体の打点を一律に格子へ丸めてはいない。

参考にした公式の操作・配置資料と、このゲームへ取り入れた要素:

| [maimai公式：遊び方](https://maimai.sega.com/play/howto/) | 同時入力をアクセントにする構成、内外へ動く軌道の発想 |

これらは配置を考える参考であり、他作品の譜面データの移植ではない。このゲームにないスライド・AIR判定などは追加していない。

## データと再生成

270ノーツ、ロング内の切断を含め424判定、ロング14本、方向付き105ノーツ。BPM98、`offsetMs:110`、`beatZeroMs:-90`、14区間の変拍子、`displayLevel:0`（自動算出）を維持。Easy・Normal・互換譜面・音源・ステージ演出は変更していない。

改作前の作者版は [authored-hard.json](../Tools/ChartDesign/Seisakuchu/ZeroHardRemix/authored-hard.json) に保存した。SHA-256は `b069bd8920a3865245e0302d7463c0bbca700a12fb7959b9c176f7ba88799b99`。各ノーツの対応と追加打点の音響照合は同じフォルダーの `provenance.json`、配置検証は `validation.json`、成立する切断時刻と振り方向の一例は `cut-plan.json` に記録した。切断計画は本編の譜面形式には追加していない。

Python・NumPy・SciPy・ffmpegを用意し、リポジトリのルートから実行する。生成先は本番とは別のフォルダーにする。後日手編集した現行譜面を、この生成結果で上書きしないこと。

## 検証

Unity 6000.3.9f1の本編ローダーで、超ロング2本の共通制限時間・50回・単純な外側単発、その他の同時ロングの全フィールド保持を確認する。生成時はヘッダーの一致、全ロングの各切断、座標、音源長、矢印への進入と振り抜きを検査する。2連・3連を含む最短の同じ手の切断間隔は約207ms。超ロング中の単発前後は、往復距離に応じて連打の切断時刻に余裕を置いた。

自動プレイの検証は `cut-plan.json` の経路を使い、切断時刻・位置・ロング内の連番と回数、超ロング中の追加単発の視認性を照合する。これはスクリプトで判定を投入する本編動作確認であり、センサー入力や実際の手振りのテストではない。実行後は撮影用スクリプトを削除し、ユーザーのシーン・ウィンドウ配置・設定・スコアを復元する。

第2稿の検証結果: 関連EditModeテスト50件成功、本編の録画はResultまで到達し270ノーツすべてPerfect、全424切断が計画と一致した（超ロングは合計100切断）。追加単発8個の出現から切断まで240フレームを確認し、全て画面内、ロング本体との投影矩形の重なりは0だった。残数文字の余白・縁を含む外接矩形との重なりは最大約0.4%で、該当フレームも画像で視認できることを確認した。`verify_capture.py` と `autoplay-validation.json` に照合処理・結果を残す。確認したカメラ設定・720p録画での結果であり、全設定や実機入力を網羅した結果ではない。

動作経路の検査は、金ノーツを左右の位置に対応する手で切る経路に基づく。金ノーツのすべての手の選択や、実機での振り心地を保証するものではない。
