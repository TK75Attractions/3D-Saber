# Zero -狂奏曲-：作者版Hardからの改作

2026-10-13、第5稿。サビの両手アクセントを増やし、前半の片手フリックへ反対の手の弧状配置を足す発展形を後半に追加した。BPM・OFFSET・既存270ノーツの時刻、全ロング、超ロング中の単発8個を維持する。


## サビの同時切りと後半の発展形

同時入力を24組から51組へ増やした。第1ピークは5→13組、最終ピークは4→23組。通常の金同時切りを16組配置し、サビ内のアクセントとフレーズ終わりで両手を使う。金は左右へ離して置き、片手にノーツを重ねない。既存の打点に反対側を足した27ノーツなので、前回合わせたリズムは変わらない。

後半の第81〜84小節には、前半の3連・2連フリックのリズム、座標、矢印を引用した4つの発展形を置く。片手の形を保ったまま、反対側に矢印なしの単発3個を弧状に追加する。2連の引用は最初の方向にもう一度返して3連へ伸ばす。

| 前半のモチーフ | 後半の発展形の開始 | 追加する動き |
| --- | --- | --- |
| 第31小節の赤3連 | 第81小節・134.714秒 | 青を左下から内側上方へつなぐ |
| 第43小節の青2連 | 第82小節・138.081秒 | 青を3連へ伸ばし、赤を右上から外側下方へつなぐ |
| 第45小節の赤3連 | 第83小節・141.449秒 | 青を内側上方から外側下方へつなぐ |
| 第47小節の青2連 | 第84小節・144.816秒 | 青を3連へ伸ばし、赤を右下から内側上方へつなぐ |

これは現在の自由切りノーツで作るスライド状の動きで、保持・接触を要求する新しいスライド判定ではない。小さなモチーフを発展させて再利用する一方、2小節・4小節全体の色順とリズムをそのまま使い回す箇所は増やしていない。金の両手割り当てを左右位置で固定した経路で、入口・切り返し・出口まで検査する。

`revision5.py` が生成器。`provenance.json` の `motifDevelopments` に引用元と発展先・反対側のノーツの対応を保存する。第4稿のインデックス付き資料は `revision4BarPhrases` / `revision4ContinuousFlickRuns` として履歴に残した。

| 34.306 | 4.926333秒・11回 | 4.918333秒・11回 |

このゲームのロングは、制限時間内に表示された回数だけ繰り返し切るノーツ。各切断の等間隔入力を要求しない。超ロング2本の共通期限は音源上110.473秒。途中の矢印なし単発8個は、左右の外側上段（x=±2.5、y=1.5）の固定レーンに残し、時刻を拍へ合わせた。検証・録画用の50回の経路は、単発へ手を伸ばして戻る時間を空けながら8分拍に載せる。最後の切断は期限内の110.224秒。実際のプレイヤーにこの経路を強制する変更はない。

## 第4稿の配置改善（第5稿の基礎）

- 赤赤・青青の2連や3連に、単発の受け渡し・短い交互を組み合わせる。同じ2連→3連の循環を区間全体へ当てはめない。小節内のまとまった往復フリックは2連39組・3連7組。小節をまたぐ同色連打も含め、振り抜きから次の入口まで検査する。
- 上段の横往復、外側の縦往復、斜めの切り返し、下段の横往復などを使い、小節ごとの中心座標も変える。方向を変える境界には自由切りも挟む。振りやすさを優先し、指定軌道へ入れない箇所は接続が成立する方向を選ぶ。
- 例えば第42〜48小節は `BRRBB → RBBRR → BRBRB → RRRBB → RBRRB → BRBBR → RBBRR`（R=赤、B=青）。2連中心、3連のアクセント、短い交互の受け渡しを混ぜる。終盤の11/8の4小節も別々の手順にした。
- 連打の入口・出口と自由切りの実際の振り方向まで含めて、全曲を通して成立する経路を選ぶ。句末・同時アクセントの矢印は、この経路を壊さない範囲に絞った。
- 同時切りと同時ロング・片手ロングへの応答は計24組を維持。静かな区間の休符、全打点時刻、ノーツ数、ロングの回数・制限時間も維持する。

## 反復の確認

第3稿では32〜33小節の配置が同一で、42〜48小節にも2小節・4小節の同じ色順とリズムが再登場していた。第4稿では、通常配置の隣接小節で同一配置が続く箇所は0、密な2小節・4小節単位で色順とリズムが再使用される箇所も0になった。

位置をわずかに変えて重複判定だけを回避しないよう、複数小節の比較では位置や矢印を除いた「小節内の拍・色・回数」を使う。5/8・11/8など実際の小節マップで区切り、空小節がなく平均3ノーツ以上ある通常配置の窓を全曲で比較する。長い連打が継続中の小節と固定レーンの単発は、指定された見せ場を残すため別扱い。比較条件と変更前後の結果は `validation.json`、小節ごとの色順・配置方針・実際の矢印は `provenance.json` の `barPhrases` に記録する。

## リズム修正の根拠

第3稿では、確認済みの音源上の拍原点20ms、98 BPM、変拍子マップを使い、Hardの打点を8分拍にそろえた。第4稿でも全時刻を維持する。全体OFFSETは変更していない。密な連打を個別に四捨五入すると2打が同じ拍に潰れる箇所があるため、元の順序と打数を保つ経路を選んだ。別の手の入力が120ms以内に割れていた応答は同じ拍へまとめ、最後の同時打ちは参照音源の最終クリック（170.530秒）へ合わせた。

270ノーツ中234個を1ms超修正し、うち177個は40ms超。最大移動は最後の同時打ちの約205ms。例として6.235→6.142秒、66.610→66.449秒、88.860→88.796秒。音源の正規化された立ち上がり強度（±45ms内の正のスペクトルフラックス）の平均は0.703→0.935となった。これは音響的な補助指標であり、楽器を分離して全音符を採譜した証明ではない。メトロノーム解析の根拠は [BPMと小節マップ](SeisakuchuTiming.md) を参照。

録画のロング切断音も8分拍へそろえた。期限を等分した切断音で不用意なハネが生じないよう、回数を満たす拍を期限内から選ぶ。ゲームのロング判定仕様には変更を加えていない。

## 検証

Unity 6000.3.9f1の本編ローダーで、超ロング2本の共通制限時間・50回・単純な外側単発、その他の同時ロングの時刻以外の保持、OFFSET込みの実再生時刻と8分拍の一致、速い同色フリックの切り返しと進入方向を確認する。生成時はヘッダーの一致、全ロングの各切断、座標、音源長、矢印への進入と振り抜きを検査する。超ロング中の単発前後は、往復距離に応じて連打の切断時刻に余裕を置いた。

自動プレイの検証は `cut-plan.json` の経路を使い、切断時刻・位置・ロング内の連番と回数、超ロング中の追加単発の視認性を照合する。これはスクリプトで判定を投入する本編動作確認であり、センサー入力や実際の手振りのテストではない。実行後は撮影用スクリプトを削除し、ユーザーのシーン・ウィンドウ配置・設定・スコアを復元する。

第5稿の関連EditModeテスト60件成功。サビの同時切りと金の左右間隔、4つの発展形の引用元との一致と反対側の経路を追加検証した。本編はResultまで到達し297ノーツすべてPerfect、全451切断が計画と一致した。追加単発8個の出現から切断まで240フレームを確認し、全て画面内でロング本体との投影矩形の重なりは0。残数文字の余白・縁を含む外接矩形との重なりは最大約0.44%。録画結果は `verify_capture.py` と `autoplay-validation.json` に記録する。録画用の振り幅も経路監査と同じ前後0.25。確認したカメラ設定・720p録画での結果であり、全設定や実機入力を網羅した結果ではない。

スマホ向けの全曲映像は [Zero Hardプレイ映像](https://zero-hard-play.metuji48.chatgpt.site/) で確認できる。サビと後半の発展形・超ロングへ移動するボタンがある。

動作経路の検査は、金ノーツを左右の位置に対応する手で切る経路に基づく。金ノーツのすべての手の選択や、実機での振り心地を保証するものではない。
