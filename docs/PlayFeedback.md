## 今回の7案

| 元候補 | 実装 |
|---|---|
| ② 不受理の理由 | LEFT HAND / RIGHT HAND、DIRECTIONと正方向の矢印、TOO SLOW。手違い・速度不足はノーツに触れて反対側へ抜けた操作だけを観察し、静止、追跡リセット、ワープ、同じ側への戻りを除外。速度不足は閾値の35%以上の明確な動きに限定。方向違いは既存の逆方向拒否が確定した時に説明。1ノーツ650ms間隔。スコアへのペナルティは追加しない。 |
| ③ Miss | 対象付近に×とMISS。成功の光や振動と混同しない、発光しない短い表示。部分達成ロングは既存の最終評価を1回だけ表示。 |
| ⑤ 判定位置 | 切断付近の外側・下へ小さな背景付きラベル。最大8個を再利用し、近い表示は下へずらす。画面端で重なる古い表示は最新の判定へ更新。EARLY/LATE、ロング達成数、誤方向の注意を維持。旧HUDの中央下の重複判定は停止。 |
| ⑥ コンボ節目 | 50の倍数で短いCHAIN表示。標準では小さく拡大し、LOWは静止表示。全レーンを光らせない。 |
| ⑧ FC維持 | 右上にFC READY / FC ACTIVE / FC LOST。開始前を達成扱いせず、BadまたはMiss以降は回復しない。色だけでなく文字でも状態を示す。 |
| ⑨ 曲の締め | 全ノーツの判定と曲音源の終了を待ってFULL COMBO / TRACK CLEAR、最高コンボとスコア、短いライン。最終PerfectにはLAST CUT。最終MissでもTRACK CLEARが成立。既存のリザルト遷移時刻は変えず、余韻の時間内に収める。 |
| ⑩ 控えめ設定 | 選曲画面のEFFECTS: FULL/LOW。クリック・ノーツ斬りの双方、設定保存に対応。LOWは切断火花を8→2、光の強さを30%にし、床／舞台反応とHUDの拡大を抑える。刃・ノーツの本体・判定文字の可読性は維持。 |

①Great/Goodへの追加バースト、④速度で刃本体を暗く細くする表現、⑦ロング途中の追加点灯は採用していない。既存の切断、効果音、振動、ロングのひびと残数表示を引き続き使う。

## 接続と検証

`GamePlayManager`が専用プレゼンターを生成してTickを駆動。`NoteSpawner`の生成通知、確定判定、Miss、不受理説明を購読し、シーン終了で解除する。切断の保留・成功判定と説明用の接触履歴は別に持つ。同じ判定呼び出し内でノーツの検索結果を共有する。

判定に使う英数字は曲開始前にフォントへ登録する。記号は専用のGraphicとCanvasRendererで描き、テストでは生成された頂点も確認する。実時間テストには最大フレーム間隔と取りこぼし時刻の診断を加え、404ノーツ成功という既存の検証条件は維持する。

`PlayFeedbackTests`は点／ブレード、手違い／速度不足、戻し・静止・ワープ・期限・リセット・速度回復、IMUによる方向救済、FC、終了条件を検証する。`PlayFeedbackPlayTests`は実Game/SongSelectシーン、表示上限と寿命、設定保存、LOW時の描画量、Perfect限定を検証する。

実機センサーの体感とプロジェクターへの実投影は未確認。実シーンの撮影では人工ノーツ・人工操作を使用する。継続的なFPSの実測は別途必要。
