# 音声と譜面の同期

## 時刻の意味

ノーツの到着時刻は `note.time / 1000 + chart.offsetMs / 1000 + extraOffsetSeconds + GameSession.JudgmentOffsetMs / 1000`。最後の項は採点だけでなく、見た目の到着も動かす。正の値は到着を遅らせる。

`note.time` と曲オフセットは音源に対する制作データ。判定調整はプレイヤーの設定であり、両者を混ぜて保存しない。エディターの波形は制作データの時刻を示す。

## 2026-09-17 の確認と修正

複数曲で、内蔵スピーカーの音にノーツ到着を合わせるには約+125msが必要、という報告を受けた。以下を数値で確認した。

- ゲームの時計は以前、予約したDSP開始時刻だけから算出していた。開始時にメインスレッドが止まり、実際の音声開始が遅れると、その差が曲の途中でも残る。650msの負荷を与えた再現条件で確認した。現在は実際の再生サンプルが進んだ時点でDSP基準を合わせ直す。その後は同じDSP時計で進み、負の先読み時間・練習のループ・曲終了後の余韻を維持する。
- エディターは以前、再生ボタンを押してからの壁時計でカーソルを進めていた。現在は `AudioUtil.GetPreviewClipSamplePosition` と再生状態を参照する。途中シーク・停止も実音声に追従する。
- エディターはゲームの判定調整を無視していた。現在は「ゲームと同じ表示補正」で同じUnity Editorの設定を再生カーソルに反映できる。波形や保存データは補正しない。補正をOFFにすると音源本来の時刻を表示する。
- 再生し直す際には前のAudioSourceを停止し、サンプル位置と同期状態をリセットする。

通常起動の実ゲームシーン（Epilogue・Andalusia）では修正前でもDSP時計と音声カーソルはほぼ一致し、まれな読み取り境界の差は約1バッファだった。このため、開始遅延だけを「報告された125msの全原因」と断定しない。

## 検証範囲と限界

検証環境の設定は48kHz・DSPバッファ1024サンプル×4。バッファの総容量は約85.3msだが、これをそのままスピーカーの実遅延と見なして差し引くことはしない。音声APIの再生位置は、空気中の音と画面の発光を測った結果ではない。出力ドライバー・スピーカー・画面を含む実遅延は、同期した録音・映像などによる追加測定が必要。

保存済みの判定調整値と既定値は維持する。修正後に必要な残差を確認する際は、曲データを動かさず判定調整を使う。ビルドとEditorのPlayerPrefsは別保存なので、双方の設定を揃えて比較する。

回帰テストは遅れた実再生との同期、先読み、再再生、ループ、音源終了後、エディターでのサンプル位置・+125ms補正・シーク・一時停止・外部停止・制作データ不変を確認する。実機で「0msなら必ず一致する」と保証するテストではない。

参考: [Unity timeSamples](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AudioSource-timeSamples.html)、[DSPバッファ](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AudioSettings.GetDSPBufferSize.html)、[Unity 6000.3 AudioUtil](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.3/Editor/Mono/Audio/Bindings/AudioUtil.bindings.cs)。


## 2026-09-19 曲ごとの同期確認と選曲プレビュー修正

- 対象は 2_23_AM / Andalusia / ElDorado / Epilogue / Morning / 揺籠。各曲を本編の `LoadAudio` で読み込み、PCM波形を元音源の別デコードと2・20・60・120秒で照合した（短い曲では120秒を除外）。比較区間の時間差はいずれも0サンプルだった。音源形式による先頭位置の差はこのWindows環境では再現しなかった。
- 全尺の譜面時刻と帯域別の立ち上がりも照合した。正方向のスペクトル変化のピークは制作時刻の約6〜22ms後だが、音の立ち上がりからピークまでの幅も含むため、この値を一律に譜面補正へ焼き込まない。曲の進行に伴う大きな累積ずれは見つからなかった。全曲の譜面と音源は維持する。
- 選曲プレビューは予約時刻だけで表示時計を進めていた。再生開始直後に500msの負荷を与えると、音声位置134.200317秒に対して表示時計134.683667秒となり、約483ms先行する不具合を再現した。最初に音声サンプルが実際に進んだ時点で表示時計と抜粋終了時刻を合わせ直す。再選曲時は同期状態をリセットし、再生を止めた後は時計も止める。
- プレビューは個人の判定補正を反映していなかった。現在は本編と同じく `note.time + chart.offsetMs + GameSession.JudgmentOffsetMs` を到着時刻とする。補正で抜粋内へ移動する冒頭ノーツも表示対象に含める。譜面の保存値とプレイヤーの保存済み補正値は変更しない。
- 回帰テストは全6曲の実プレビュー音声カーソル、開始負荷、正の個人補正と曲補正の加算、抜粋境界のノーツを確認する。本編の先読み・再再生・ループ・音源終了後の時計も既存テストで確認する。

これらはソフトウェアの再生位置・表示・制作データの検証であり、実際のスピーカー音と画面の発光の同時計測ではない。実プレイで全曲に残る早い／遅いの体感は、出力先ごとの判定調整で確認する。今回の確認だけで全ての体感ずれが解消したとは断定しない。
