# 背景誤検出を消す eligibility ルールの比較(offline、2026-10-03)

read-only の調査。production のコードは変更していない。
ルールは、production の detector の**一時コピー**に環境変数で切り替えるゲートを足して評価した
(`ios/PhoneSaberSender/Tools/phone_saber_rule_study.py`)。
ラベルは `2026-10-03_background_fp_labels.csv`(画像は含まない。session / frame / 色ごとに、original PNG で見た点灯 saber の箱)。

## 結論

- **最初に production へ上げる候補は R7e(赤のみ)。ただし今は上げない。** 証拠の gate が未達(下の「足りない証拠」)。
  - R7e は、効果が大きい唯一のルール。formal 40/40、背景 benchmark 7/8 → 0/8。
    背景の赤い winner は 54 → 26。ジャンプ 17 件のうち 8 件が「検出なし」に変わる。点灯 saber の取りこぼしは 0。
  - 取りこぼし 0 は、R7e を決めた後に撮った 10-03 の session(out-of-sample)でも同じ。
- **PF22 は R7e の後に、別 commit で足す。** 単独では弱い(背景の赤い winner 54 → 54)。
  ただし、saber が映っている最中に起きたジャンプ(144936 f2552 → 壁コンセントのラベル)を消すのは PF22 だけ。
  R7e+PF22 では、ジャンプ 17 件のうち 10 件が「検出なし」になる。
- **採用しないもの**
  - 青のルール: bpf22 は効果がほぼない(1/19)。bmean225 は formal を 35/40 に壊す。
  - 「動かない候補を外す」静的ルール: 本物の saber でも frame 間の移動が 2.2px まで小さくなり、ラベルとの差が 1〜2px しかない。
- **どのルールでも直らないもの**: 手持ちカメラの映像(155919: 肌・指・机)。カメラを固定するという運用で対処する。
- **露出に弱い**: 全体を +8% 明るくすると、R7e+PF22 は背景の赤い winner を 69 件中 5 件しか消せない(clipped-white の免除が効いてしまう)。
  露出を振った実機 capture が、採用の必須条件。

  - 赤: saber が映っている 44 件 / 映っていない 80 件 / 不明 5 件
  - 青: saber が映っている 46 件 / 映っていない 77 件 / 不明 6 件

  これを満たせば real、満たさなければ bg。
- detector の再現性
  - 10-02 / 10-03 の session(356 色 frame)では、端末の winner score と完全に一致した。
  - 09-30 / 10-01 の一部(151 件)は、当時の古いビルドとずれる。offline の結果は現行の detector を表す。
- formal は 40 fixture、背景 benchmark は 8 枚(どちらも上の 129 frame とは別の評価器)。
- 偏り:
  - 点灯した赤の saber が連続 frame で映っているのは 144936(8 frame)だけ。
  - 部屋は約 3 つ。日中の capture は 152037 だけ。

## 一つずつ抜いて閾値を決め直す(leave-one-session-out、赤、検出の外で後から適用)

- R7e の太さの閾値 T を、残り 22 session で「real を1つも落とさない最大値」に合わせ、抜いた session に当てた。
  - T はほぼ 4.8 になった。抜いた側で消えた bg は 59 件中 34 件、real の取りこぼしは 1 件(002509、T=5.2 のとき)。
- PF の床 F も同じように合わせた。
  - F はほぼ 0.33 になった。消えた bg は 5/59 件、取りこぼしは 1 件(234740、F=0.46 のとき)。
- 読み取れること:
  - session ごとに閾値を合わせると、その値はいつも real 側の端に張り付く。
  - session だけで決めた T=4.8 では formal の正例(red_long_core_line_1000 の d240 4.49、red_390 の 4.74)が落ちる。
    **閾値を縛っている本当の制約は formal corpus** で、R7e の 4.2 もそこで決まっている。

## 時間的な静的ルールについて

eligible な候補の中心が、前の frame からどれだけ動いたか(最小値):

| 群 | n | ≤2px | ≤4px | 中央値 |
|---|---|---|---|---|
| real(144936 のみ) | 52 | 0 | 3 | 9.1px(最小 2.2px、青の saber を片手で持って静止) |
| bg | 200 | 46 | 71 | 8.1px(固定カメラのラベル・カラビナは 0〜1px、揺れた 010049 は 8px 以上) |

- 固定カメラのラベルなら確実に外せる。しかし、静止した本物の saber との差は 1〜2px しかない。
- 「saber を静止して持つ」capture がないので、取りこぼしを測れない。
- 手持ちカメラでは効かない。
- **eligibility の hard rule には使わない。** 使うとしても、将来、修正 A 系の順位付けのヒントとしてだけ。

| 1.00 | 54 / 5 | 26 / 1 | 0 | 17 → 7 |

- 明るくすると、ラベルや白文字が clip≥0.35 の免除を満たし、R7e も PF22 も効かなくなる。
- 暗くすると、base だけでも背景の誤検出が半分近くに減る。
- 露出の上限を短くする実験スイッチ(63eca9d)の効果は、R7e と同じ方向に効くと予想できる。

## 推奨

1. **最初に上げる候補は R7e(赤のみ、閾値は shadow と同じ 0.35 / 4.2 / 3.5・0.60)。**
   次の「足りない証拠」がそろってから、修正 A・B とは別の commit で入れる。
   - DebugVideoRecorder の eligibility 再構成も同時に直す。
   - formal 40/40、背景 bench 0/8、本表の再計算(このツール)を確認する。
   - そのうえで、実機での再試験を依頼する。
2. 次に PF22 を別 commit で入れる。R7e の後、同じ capture で shadow PF22 の取りこぼしが 0 だった場合に限る。
3. 青、静的ルール、mean 下限は上げない。
4. 運用上の対策(コード変更なし): カメラは三脚で固定する。レンズの前に指や手を出さない。
   壁のピンク・赤のラベルは、可能なら画角の外に出す。

### 足りない証拠(CLAUDE.md §1「証拠なしに threshold を変えない」/ 受け入れ基準)

- (a) **点灯した赤 saber の真の分布**
  - 端末側の shadow 判定つきの lit 赤 saber は、まだ 1 session・8 frame しかない(144936。端末の d240 は offline と一致)。
  - 必要なもの: 0.5〜3m の距離、端から見た向き、速い振りのブレ、片手で静止。これを部屋 3 つ以上で。
- (b) **露出**: 自動露出と上限 1/120(または 1/100)の両方。日中と夜の両方。+8% で効かなくなるため必須。
- (c) **session 全体での集計**
  - shadow R7e / PF22 の判定は、保存された frame(1 bundle で最大 12 枚程度)にしか残らない。
  - 区間ラベル(saberあり / saberなし)ごとに「winner が shadow で却下された frame 数」を全 frame で数える必要がある。
    あわせて、saberあり区間で却下された frame の PNG を数枚保存する。
  - これは diagnostics の追加で、production の認識は変わらない。§2 の範囲で自律的に進めてよい作業。
- (d) PF22 の shadow は、まだどの capture にも入っていない(ead64f7 以降のビルドが必要)。
- (e) saber を静止して持った frame。静的ルールを将来検討する場合だけ必要。

### ユーザーに撮ってほしい Debug Recording(具体的な手順)

準備:
- main(ead64f7 以降)の Debug build を iPhone に入れる。
- カメラは三脚で正立・固定する。診断色は BOTH。
- 背景の赤い物(ラベル、カラビナ、壁コンセントのラベル)は**片付けない**。

録画 1 回目(露出は auto、合計 5 分以内。区間ラベルを切り替えながら撮る):

1. 「saberなし」20 秒: saber は消灯するか、画面の外に置く。
2. 「saberあり」赤だけ:
   - 点灯した赤 saber を、カメラから 0.5m・1.5m・3m の位置で、それぞれ 3 秒**静止**して持つ。
   - 1.5m で先端をカメラに向けて(端から見た向き)3 秒。
   - ゆっくり振る → 速く 5 回振る(うち 2 回はカメラの方へ突く)。
3. 「saberあり」赤い物の近く: 点灯した赤 saber を、ラベル・カラビナ・コンセントのラベルの 30cm 手前で各 3 秒静止させる。
   その後、それらの前を横切るように 3 回振る。
4. 「saberあり」青だけ: 手順 2 と同じことを短めに(0.5m・1.5m・3m の静止、速い振り 5 回)。
5. 「赤い物隠し」10 秒: ラベル・カラビナを布で隠す。saber はなし。

録画 2 回目: 露出の実験スイッチを 1/120(東日本なら 1/100)にして、手順 1・2・3 だけを繰り返す。

可能なら後日: 別の部屋(教室、日中の窓際)で、1 回目と同じ手順。採用判断の目安は**部屋 3 つ以上**。

採用の判定基準(案):
- saberあり区間で、original PNG に点灯した赤 saber が映っている frame に、shadow R7e の却下が **0 件**。
  対象は 300 frame 以上で、自動露出と上限付き露出の両方を含む。
- saberなし区間で、赤の winner の 80% 以上を shadow R7e が却下する。
