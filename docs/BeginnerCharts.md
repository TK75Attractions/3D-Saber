# Easy / Normal 全曲改訂（2026-10-21）

全14曲のEasy / Normal、計28譜面を初心者向けに再構成。`chart.json` はNormalと同一に更新した。Hard、隠しE、音源、既存meta、難易度表示、BPM・拍子・オフセット等の時刻メタデータは変更しない。

## 今回の条件

- Easyは表拍だけ。左右を合わせた実カット間隔を四分音符以上、さらに500ms以上とする。ロング内部も対象。
- Normalの裏拍は独立した「表・裏・表」の短いまとまりだけ。孤立裏拍、裏拍だけの反復、「裏・表・裏」は不可。複合拍の分割を二分割と混同せず、セル間に休みを設ける。
- 音のある導入と曲中の実カット間に、5秒以上の空白を作らない。ユーザーが明示した末尾の余韻は埋めない。冒頭の実際の無音も維持。
- 各譜面で最低1回フリックを使用。Easyは2〜4回、Normalは2〜9回。方向は上下を基本にし、準備・回復の余裕を置く。
- 各ロングは無理なく2回切る形（count=2）に統一する。譜面内のロング本数を2本に制限する意味ではない。保持だけでは完了しないゲーム仕様に合わせ、実カット予定と最後の切断後の余裕を検証。

## 曲らしさと変化

既存の主題の輪郭、小さな上下移動、左右の受け渡し、両手の着地、静かな区間と密な区間の差を使う。裏拍を除いて主題が消えた箇所は、既存の主打か、音源の立ち上がりを確認できる主拍で再構成した。均一な四分列が長く続く箇所には弱い句末の休みを作る。数合わせのフリックや、持続音の音量だけを根拠とする補完は採用しない。

Claude Codeの実モデル `claude-opus-5-5` / `--effort max` と設計・反論・改訂案をやり取りした。具体的な採否と留保は [議論記録](../Tools/ChartDesign/Beginner20261021/DISCUSSION.md) を参照。AIによる議論・数値検査は実機の遊び心地の保証ではない。

## 拍の根拠と限界

- `pulse-map.json` は譜面生成と別に固定した参照拍。SHA-256で変更を検出する。検査器は生成コードを呼ばず、保存JSONを読み直す。
- 通常曲は既存の時刻対応を利用。校歌Epilogueは既存の楽譜由来の拍と時刻の対応表を使い、先頭BPM92だけで全曲を換算しない。1296msのオフセットは一度だけ適用。
- 6/8は付点四分の主拍。製作中（Zero）の5/8・11/8は内部の分割が未確定なので、メトロノームで確認済みの小節頭だけを使用する。
- アンダルシアの拍は従来の音源推定地図に基づく。RUSH Eの120BPMは編集用の座標であり、音楽の拍とはみなさない。RUSH Eは保存済み音源解析のPLP、既存の音源整列済みE打点、疎な導入と終止の打点から拍を推定した。いずれも楽譜による全曲確定や人間の聴感確認が済んだとは扱わない。密な元E譜面では65ms以内の一致だけで位相を立証できず、PLPの位相ずれ・倍半テンポ解釈は保証外。アンダルシアの拍子境界・3/4との解釈の違いも保証外。
- RUSH Eで新しい時刻を機械的に120BPMへ量子化していない。元のHard/Eを修正せず参照する。

## 保守・検証

設計データは `Tools/ChartDesign/Beginner20261021/`。`plans/` はロング内部を含む全カット時刻・手・方向・元打点を記録し、Unityの実ローダー／生成／採点テストから読む。過去の5曲設計・RushE設計の下位譜面計画より本改訂を優先する。Hardの旧計画は保持する。

```powershell
python -m unittest discover -s Tools/ChartDesign/Beginner20261021 -p test_verify.py -v
python Tools/ChartDesign/Beginner20261021/verify.py --candidate . --source <改訂前の曲別JSONフォルダ> --output audit.json
```

生成コード `rechart.py` は改訂前の全難易度JSONと音源特徴量を入力にするため、現行譜面を入力にして上書き生成しない。原本スナップショット・特徴量・解析コード・比較図・Claude全文・テストXMLは制作作業フォルダの `Tools/BeginnerCharts20261021/` と `Tools/ChartToolsFollowup20261016/verification/` に保管。生成時の特徴量フォルダの親に `frozen-pulses.json`（採用した`pulse-map.json`と同一）と `rush-music-pulses.json` を配置する。

```powershell
python rechart.py --source <改訂前の曲別JSONフォルダ> --features <特徴量フォルダ> --output <候補フォルダ>
```

実音の位相や身体操作を数値監査だけで断定しない。後から拍を訂正する場合は参照拍地図の根拠・改訂理由を明示し、譜面・カット計画・独立監査・Unity検証をまとめて更新する。
