# Saber Tap Studio

[スマホで開く](https://saber-tap-studio.metuji48.chatgpt.site)（ログイン不要）。音源・譜面・設定は各端末のIndexedDBへ保存します。音源解析APIや外部CDNは使いません。ユーザーが「共有する」を選んだ場合に限り、OSの共有先へファイルを渡します。

## 4つの作業画面

1. **録る**：音源を開き「録音開始」。左は青、右は赤です。色を青・赤・金に固定すると、パッドの地と見出しもその色だけになります（どこを押してもその色）。タップした位置・時刻を記録し、素早い動きは8方向のフリック、長押しはロングになります。入力結果（タップ／フリック／ロングと補正量）は、縦ではパッドの下、横ではパッドの下端に出ます。録音中は設定・ライブラリ・別タブへ移れません。停止後に「元に戻す／やり直し／録り直す／▶聴く」を使えます。
2. **直す**：横が実際のX位置、上が先の時刻の縦タイムライン。矢印とロングの長さを表示します。ロングは棒の部分を押しても選べます（始点が表示区間の外でも）。ノーツがまだない下書きでは、グラフの中に入れ方を表示します。空白のタップでシーク、ドラッグで移動。表示幅を変えても、見ていた区間の真ん中を保ちます（再生位置へは「再生位置へ」）。ノーツの追加は「＋置く」で、今の再生位置にそのまま置きます（録音用の入力補正・速度は混ぜません）。重なったノーツは一覧から選択します。一覧の行は「番号・時刻・色・矢印・回数と長さ・位置」で、選んでいる行に印がつきます。
3. **確かめる**：ノーツのプレビュー、試聴、密度、見直し候補。入力パッドはありません。診断候補を選ぶと「直す」へ移ります。
4. **渡す**：「① 譜面」（JSONのダウンロード／共有）→「② 同じ音源」の順。②は、ゲームが読める mp3／ogg／wav なら「元の音源を保存」、M4A などは「音源をWAV保存」を目立たせます。その下に実際のファイル名、音源入りバックアップ。読み込みは「曲・保存」に集約しています。ノーツが0個・BPM未設定・別難易度と設定が違う、の注意を1件ずつ上に出します。

最初の画面の「続きを開く」で、前回の下書きを1回で開けます。知らせは画面のいちばん上（曲名の帯）に出て、録音開始やパッドを隠しません。タブを切り替えても、それぞれのタブのスクロール位置を覚えています。

縦390×664では262pxの入力パッドとUndoが画面内に収まります。プレビューは「確かめる」で使い、横向きの録音画面は左がプレビュー・再生、右がパッドです。端末の文字サイズ・ソフトキーボード・ブラウザUIで見える範囲は変わります。

## BPM・入力と設定

- 新しい音源は **BPM未設定・拍への補正OFF・カウントOFF・タップ音OFF** で開始します。数値入力か「タップでBPMを測る→BPMに適用」でBPMを確定してから、必要に応じて拍への補正を有効にしてください。BPMを決めても既存ノーツを自動で移動しません。BPM未設定のまま録ったノーツは、BPMを初めて決めたときに時刻を保ったまま拍の番号を数え直すので、テンポが一定の曲を「テンポが変わる譜面」と取り違えません（「元に戻す」で未設定へ戻すと元の値に戻ります）。設定の「曲を流す」で、その場で曲を聴きながら拍をたたけます（録音はしません。遅く聴く設定でも1.0倍で流し、押すたびにたたいた記録を消します。設定を閉じると止まります）。
- 従来の下書きと外部JSONの120 BPMは未設定と推測しません。既存JSONを開いた直後の入力補正はOFFです。未設定のまま書き出す場合、ゲームとの互換値120をJSONに入れることを出力画面で案内します。入力した時刻は保持します。
- 設定は「曲設定／打ち方／この端末／聴き方」の4群。曲設定は「BPM・難易度 → 曲を流す・タップでBPMを測る・BPMに適用 → 拍の始まり・オフセット・表示レベル」の順です。曲名は「曲・保存」で変更します。ノーツがある下書きの難易度変更には確認があり、別の下書きを残したい場合はコピーを使います。
- 「近いときだけ」は最大±20／35／50msと刻み幅から求める範囲内だけ補正します。4分・8分・16分・8分三連を選べます。スロー時も実時間の許容幅を維持し、ロングの始点と終点は別々に補正します。
- 長押しのしきい値は初期300ms、150〜1000msで変更できます。自動ロング回数は新しい入力だけ、Easy/Normalは2拍、Hardは1拍ごと。手動回数と既存譜面は変えません。
- 位置グリッドは自由／0.25／0.5／1.0。入力色・音量・速度・入力補正・しきい値などは下書きとバックアップに保存します。「この端末」という区分は操作上の分類で、機器別の自動校正や全下書きへの設定同期はありません。
- BPM未設定や可変テンポ検出時は前後5秒移動、通常は拍子変更・OFFSETを考慮した前後の小節移動です。波形もタップ・ドラッグしてシークできます。「録る」では、波形の上の時刻の行も含めた帯全体が押せます。

## 録り直し・個別編集

「区間」の画面の先頭にある「今の位置から最後まで録り直す」は、A=今の位置・B=曲の終わり・置き換えONを1回で決めます。区間がある間はボタンが「区間 ON」になり、同じ画面の「区間を解除」で戻せます。「確かめる」にも「区間・ループ」があり、「今の位置からくり返し聴く」で2小節（その位置の拍子で数える。3/4なら6拍。BPM未設定やテンポが変わる譜面では5秒）をループします。

「区間」でA/Bを設定するとAから再生しBで停止します。「区間内を録り直す」がONの間は、パッド上に範囲と置き換え警告を出します。入力した場合だけ、再生した区間を置き換えます。途中停止より先・Aより前に始まるロング・入力なしの録音では元のノーツを残します。

「元に戻す」は1回の録音または編集を取り消し、「やり直し」はそれを復元します。BPMを決めたあとの「元に戻す」は「BPM未設定」まで戻ります。「直す」にも「元に戻す／やり直し」があり、選んでいたノーツが残っていれば選んだままです。「録り直す」は直前の録音前へ戻り同じ位置から再挑戦。「▶聴く」は直前のテイクを確認します。拍との差は平均絶対差の目安で、シンコペーションや拍裏にも反応するため、遅延の測定値ではありません。

選択ノーツは画面下のパネルで編集します。「削除」は見出しの横にあり、消すと時刻の並びで次のノーツを選んだままになるので、打ち間違いを続けて消せます（二度押しで2個消えないよう、消した直後0.4秒は受け付けません）。数値はEnterまたはフォーカス移動で即反映し、適用ボタンは不要です（打ちかけのまま矢印や色を押しても、先にその値を確定します）。変更した項目だけを書き換え、時刻以外の編集では元のbeatを保ちます。空欄や音源外の時刻は採用しません。

縦390×664では、パネルを開いた直後にスクロールせず「削除・閉じる／前へ・次へ（見出しに番号・時刻・色・回数）／10ms早く・10ms遅く・聴く／3×3の矢印／色（青・赤・金を1回で）・拍にそろえる・矢印の変更後に次へ」まで見えます。スマホで録ったあとはフリックの向きを直すことが多いので、矢印は折りたたみません。時刻・色・カット回数の欄はその下、X/Y・長さは「位置・ロングの長さ」にあります。横向きでは矢印の下の段からスクロールします。

## まとめて直す・診断

「直す→まとめて直す」で全曲／A–B・色・操作を選び、対象件数を確認してから適用。各操作は1回でUndoできます。選んでいたノーツが残っていれば選んだまま（値は新しく）、消えたら選択パネルを閉じます。「曲全体」のときはA・Bの欄を隠し、確認後の適用ボタンに操作と件数（例「時刻移動を 12 個に適用」）を出します。

- 時刻移動、区間コピー、左右反転（色の交換は任意）、上下反転、位置移動。
- 同時押しの高さ・同時ロング回数・左右対称化。ロングの実時間長は維持します。
- **25ms以内の時刻合わせ**：グループ先頭から25ms以内だけを先頭時刻へ移動。連鎖して別の拍へ広げず、beatの差分とロング長を維持します。
- 近い拍への補正、ロング終端の整列、色・矢印・ロング回数の一括変更、削除、完全重複の除去。
- 時刻変更・コピーで音源外へ出る操作は全体を中止。空欄は0とみなしません。BPM未設定の間は拍への一括整列も止めます。

診断は音源外・配置外・重複・同じ手のロング重なり・急移動に加え、25ms超〜120ms未満の同じ手、400ms以内の同方向、Easy/Normalの間隔・同時数などを候補にします。金はどちらかの手で切れるため、両手必須として数えません。難易度の生成基準や既存曲の分布はゲームの禁止規則ではなく、自動修正もしません。本編のセイバー判定を再現する採点機能ではありません。

曲設定では拍・前後ノーツへの移動、現在位置を拍の始まりにする操作、名前付き目印を使えます。目印は下書きとバックアップに保存します。確認用のA–Bループ、音源とタップ・拍の個別音量は従来どおり利用できます。

## 曲・保存とバックアップ

「譜面を開く」で読み込んだJSONは、今開いている曲の新しい下書きになります（ボタンの下に行き先の曲名、読み込み後にファイル名・曲名・難易度を表示し、一覧を閉じます）。ライブラリは共有するaudioIdで曲をまとめ、難易度・ノーツ数・編集中・更新日時・前回出力日を表示します。同名でも別音源は混ぜません。ない難易度の「＋」から、BPM・OFFSET・拍の始まり・拍子・座標倍率を継承した空の下書きを作れます。作成画面に「元にする下書き」（曲名・難易度・ノーツ数・BPM）を表示し、開いている曲ならその下書き、別の曲ならその曲で最後に更新した下書きを元にします。「新しい下書きを作る」を押すまで、開いている下書きと「元に戻す」は切り替わりません。通常のコピーも可能です。削除の確認には、ノーツ数・最終更新・編集中かと、「同じ曲のほかの下書きが使うので音源は残る／最後の下書きなので音源も消える」を表示します。一覧を開いたまま曲名を変えると、一覧と検索もその場で新しい名前になります。

「渡す→音源ごとバックアップ」で音源・譜面・設定を1つの `.saber` に保存できます。「曲・保存→バックアップを開く」で別の下書きとして復元します。新規読み込み・復元の音源と譜面は同一トランザクションで保存します。前回出力日は出力操作の記録で、受け手の保存完了や最新版との一致を保証する印ではありません。

同じ下書きの実編集が別タブで保存されていた場合、古い内容での上書きを止めます。「別タブで更新」が出たら手元の譜面をJSONで保管してから再読み込みしてください。再生位置や内部ノーツIDの違いだけでは編集競合にしません。

保存失敗時は未保存の表示と編集中データを保持します。上の「未保存」の行を押すと「渡す」へ移り、譜面JSONと音源入りバックアップをその場で書き出せます（バックアップは端末への保存に失敗していても、手元の譜面で作ります）。「渡す」には実際に保存されるファイル名と、ゲームの曲フォルダーでの名前（例：元の音源を audio.mp3 に改名）を表示します。ブラウザデータ削除・OSのストレージ解放・突然の終了を完全には防げないため、バックアップも保存してください。音源は100MB・20分までですが、低メモリ端末では短い圧縮音源を使ってください。

## Unityへ渡す

1. 「渡す」で `chart_easy.json` / `chart_normal.json` / `chart_hard.json` と同じ音源をPCへ渡します。共有非対応ならダウンロードを使います。出力前に、同じ音源の別難易度とBPM等が違う場合は注意を表示します。
2. **Unity内の未保存編集を保存または破棄してから**、`Assets/StreamingAssets/Songs/<曲ID>/` に譜面を配置します。置き換える元ファイルも保管してください。音源は `audio.mp3` / `audio.ogg` / `audio.wav` の採用する1つにそろえます。M4A等は「音源をWAV保存」で変換できます。
3. Unityの譜面エディターで「読込先」の難易度を選び「読込」を押します。外部ファイルを配置しても開いている画面は自動更新されません。曲名・アーティスト等はUnityの曲情報で設定します。
4. `chart.json` は欠けた難易度の互換用フォールバックで、新曲の一覧表示の必須条件ではありません。NORMALをUnityで保存すると互換譜面も更新されます。

スマホから本編のファイルを直接書き換えません。ロングは押し続けて採点するノーツではなく、同じ場所を複数回切るノーツです。継続時間を `lengthMs`、回数を `count` として渡します。

## オフライン・タイミング

HTTPSで最初に開き「オフラインで使用できます」の表示を待ちます。iPhoneは共有メニューから「ホーム画面に追加」、Androidはブラウザのインストールから使えます。保存済みデータは同じブラウザ／ホーム画面アプリから開いてください。更新時は「更新を反映」から保存後に再読み込みできます。

音声の出力時計と入力イベントの時刻を対応させ、描画フレームでは入力時刻を決めません。OFFSETは保存時に一度だけ取り除き、本編が一度だけ足します。スローでも元の音源秒数を保存しますが、音程も下がります。入力補正はスマホで打つタイミング用で、ゲームの個人判定設定を重ねません。画面から離れると停止します。

## 開発・検証

```sh
node --test tests/*.test.js
npm run check
# SABER_SONGS_DIR に Assets/StreamingAssets/Songs の絶対パスを指定すると実譜面も往復比較
```

ブラウザ回帰確認は `tests/browser-smoke.mjs` と、使いやすさの確認 `tests/browser-usability.mjs`（同じ環境変数）。画面に出す版（「曲・保存」の下、`app.js` の `APP_VERSION`）は `sw.js` のキャッシュ名とそろえます。静的HTTPサーバーを起動し、`SITE_URL`、必要なら `PLAYWRIGHT_MODULE`（Playwrightモジュールの場所）、`BROWSER_CHANNEL`（既定msedge）、`QA_OUTPUT`（画像の出力先）を指定して実行します。独立したブラウザコンテキストと合成WAVを使い、実ユーザーの下書きは操作しません。
